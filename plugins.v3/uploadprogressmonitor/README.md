# 上传量进度监控（MoviePilot V3）

版本 `0.1.8`，开发预览版。监控用户上传量，定时推送任务进度。

## 目标如何计算

**初始上传量和任务总量均为必填。** 初始量填写任务开始时账号已经记账的累计上传量，可为 0；任务总量填写本次需要增加的上传量，必须大于 0。

- 目标累计上传量 = 初始上传量 + 任务总量，自动计算。
- 任务进度 =（当前累计上传量 − 初始上传量）÷ 任务总量，限制在 0%～100%。
- 例如初始 40 TB、任务总量 10 TB，目标自动为 50 TB；当前累计 44 TB 时，已完成 4 TB，进度为 40%。

两个输入可独立选择 GB、TB、PB，支持小数，按站点口径以 1024 换算。比较使用字节数。初始量不会随检查时间变化；修改初始量或总量后，下次检查重新计算进度和首次发现达标时间。

`0.1.4` 不迁移旧的“目标累计上传量”配置，更新后请为任务重新填写初始上传量、任务总量及单位，再保存并检查。

## 配置

1. 在 MP 站点管理中添加需要监控的站点并配置认证资料。馒头需要 API Key；Audiences / NexusPHP 需要有效 Cookie 和正确的 HTTPS 站点地址。
2. 安装「上传量进度监控」，添加监控任务。每项选择站点，填写 UID、初始上传量、任务总量及单位，客户备注可选。
3. 使用“添加监控任务”增加用户，“移除此任务”删除用户；也可关闭某项“监控此任务”以暂停。最多 100 项，空白任务不参与检查。
4. 同一 UID 可绑定不同站点；同一“站点 + UID”不允许重复，避免冲突目标。
5. 启用插件。默认“每轮发送通知”开启；调试时可关闭通知，仅查看详情。
6. 勾选“立即检查一次”并保存，可在 3 秒后执行一轮。之后按周期检查，默认 cron 为 `0 * * * *`，时区为北京时间。

添加、修改、移除或暂停任务均在保存后生效。扫描中保存配置不打断当前一轮，下一轮使用新配置；关闭插件或重载时会停止当前一轮并保留已经查到的结果。

通知使用 MP 的“站点”消息类型，请确认通知渠道允许该类型。

## 每小时通知

每轮检查都会完整汇总以下三组，包括此前已经完成的任务：

- **待完成**：客户备注 / 用户名、站点、UID、当前上传量、目标上传量、进度、剩余量。
- **已完成**：客户备注 / 用户名、站点、UID、当前上传量、目标上传量。
- **查询失败**：站点、UID、失败原因、目标；如有历史成功数据，会明确标注“上次成功”的上传量和时间。

详情表格只展示当前上传量、目标、进度、剩余量、较上次变化及检查时间；初始量和任务总量在配置中维护，完整任务数据保留在通知中。直接按读取的上传量计算进度与剩余量，达到目标即标记已完成，进度为 100%、剩余量为 0。

有上次成功记录时，会比较前后两次成功查询的上传量并显示变化。馒头使用 API 字节数，观众及其它 NexusPHP 使用页面上传量数值；首次查询显示“—”，查询失败不会覆盖成功记录。累计上传量下降会提示核实，并按当前值重新判断，不保留错误的完成状态。

用户较多时按段落分批通知，不截断任务。未启用 MP 推送时只保存和展示结果；没有有效任务或配置无效时不会发起检查。

## 站点适配

| 站点 | 读取方式 | 凭据来自哪里 |
| --- | --- | --- |
| 馒头 | 官方 `POST /api/member/profile?uid=...`，读取 `memberCount.uploaded` 字节数 | 该任务所选 MP 站点的 API Key |
| Audiences | `userdetails.php?id=...`，支持新版卡片布局及旧版表格布局 | 该任务所选 MP 站点的 Cookie |
| 其它 NexusPHP | 尝试相同的用户详情页模板，支持简体、繁体和英文上传量标签 | 该任务所选 MP 站点的 Cookie |

站点选择器会为馒头、Audiences 和通用 NexusPHP 标注查询方式。其它类型的站点或深度改版的 NexusPHP 不保证适配，不能可靠解析时显示查询失败。

资料页中的导航栏可能显示登录账号自己的流量。新版卡片布局仅读取目标资料容器中的上传量字段，同时核对姓名链接和 UID 字段；旧版表格布局检查目标资料标题后面的上传量。忽略“真实上传量”等不同指标。馒头读取 API 字节数，NexusPHP 读取用户资料页显示的上传量。

不额外扣除余量，也不添加“约”字或精度提示。例如观众显示 `5.300 TB`、任务目标为 `5.30 TB` 时，直接判定完成。小数单位转换采用一致的整字节口径，目标先按原始初始量与任务总量相加再取整，避免仅因取整差异而剩余 1 字节。

单人资料隐藏、Cookie 失效、站点限流或接口错误不会中断其他任务；失败数据不当作 0 或已完成，也不会用登录用户自己的上传量替代。请求不跟随重定向，每项间隔 2 秒。

查询超时、无响应、网络 I/O 异常和 HTTP 408 / 429 / 500 / 502 / 503 / 504 会自动重试，**每个账号最多尝试 3 次**，单次超时仍为 30 秒；两次重试默认等待 5 秒、10 秒。若响应包含有效 `Retry-After`，本轮重试会至少等待其指定时间；要求等待超过 60 秒时本轮不再重试。等待可被停用插件或重载打断，日志会显示重试次数与结果。

Cookie、Key、权限、配置或页面解析错误不重试。每个账号在重试结束后只记录一次最终结果，再发送本轮汇总；重试失败仍保留上次成功的上传量与时间，不覆盖增量比较基准。

## 数据与验证范围

配置只保存任务及站点 ID，API Key / Cookie 复用 MP 站点管理配置。运行数据只保存 UID、站点名、用户名、客户备注、上传量、目标、进度和时间，不保存站点原始响应、HTML、邮箱、IP 或认证资料。详情页按文本渲染用户名和备注。

已核对官方 OpenAPI、NexusPHP 资料页及容量格式化源码，并通过合成数据与离线宿主替身测试。`0.1.1` 使用用户在本机提供的 Audiences 登录后资料页 HTML 验证新版卡片解析，用户已反馈在其 MP 中查询可用；回归测试使用重建的合成页面，未将原始 HTML 或用户私人资料加入仓库。`0.1.2` 的任务总量计算与页面显示已通过离线测试和独立页面预览。通知渠道实际送达仍需在用户环境确认。需要当前 MoviePilot V3 的 `app.sdk`、宿主调度器和站点 Oper；早期 V3 小版本的兼容性仍需确认。

测试命令（在仓库根目录，已有 pytest 和 APScheduler 环境）：

```sh
python scripts/test_offline.py
python .github/scripts/check_plugin_versions.py
python -m compileall -q plugins.v3
```
